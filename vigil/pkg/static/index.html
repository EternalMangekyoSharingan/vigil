Vigil Pkg AUR package review

Packages your AUR helper downloaded

Vigil looks in paru, yay, pikaur, trizen and pamac's build caches and reviews each PKGBUILD as text, before you build it. New or changed ones are reviewed automatically when this page opens.

How to use it

  1. Ask your helper to download a package (it shows you the PKGBUILD before building).
  2. Come here: it appears with a verdict. Open it to read the exact lines.
  3. If it looks right, press Approve. Next update, Vigil shows only what changed.

Review before every build

paru can run Vigil in each package's folder before it builds, and stop when the review finds something. Copy these lines into your paru.conf:

Terminal: python3 -m vigil.pkg review DIR --fail-on high exits 2 when anything is High.

Review a PKGBUILD before you build it

Point Vigil at the folder your AUR helper shows for review, or at a git clone of the AUR repository. Vigil reads the files as text. It never runs makepkg or any part of the PKGBUILD.

What Vigil checks

  • Look-alike names (popular name plus "fix", "patched"…; one-letter typos; known malicious names)
  • Where sources come from: bare IPs, pastebins, link shorteners, file-sharing sites, plain http, another site than the project's
  • SKIP or missing checksums on release files and -bin downloads
  • Downloads inside prepare(), build() and package()
  • Run-what-you-download: piping into a shell, eval, base64 decoding, long encoded text, chmod +x then run
  • .install scripts: downloads, services switched on, users and admin rights, cron, setuid, files outside the package
  • Writes outside $pkgdir, sudo, changes to your shell or startup files
  • History: what changed since the version you approved, new maintainer, .SRCINFO mismatch; optional AUR details

Verdicts

Don't install: at least one strong sign of trouble. Review these lines: something worth reading yourself. Looks normal: nothing matched; never a promise that it is safe.

Foreign packages already installed

Packages no repository offers (what pacman -Qm lists), checked against known-malicious and look-alike names, and their files compared with what pacman installed (like pacman -Qkk), by reading the package database.

Versions you approved

After you approve a version, the next review of that package shows what changed and marks new lines.
